# Support

Where to ask what, so you get an answer faster.

## Table of contents

Every module and section has a README. If you are lost, start at the
top-level [README.md](README.md), then the module README, then the
chapter. The [ROADMAP.md](ROADMAP.md) has the linear version with
per-phase prerequisites.

## Something is broken

A dead link, a demo that does not run, a snippet that errors against
the current library version: open a bug-report issue. Give the file
path, the line, and the exact error text. The repo is verified against
the versions pinned in `pyproject.toml`, so also state your versions if
you are not using the pinned set.

## Something is missing or wrong

A topic the curriculum should cover, a question bank gap, a chapter that
explains a concept better than it does: open a content-suggestion issue.
The editorial bar lives in [CONTRIBUTING.md](CONTRIBUTING.md) — read the
"what gets accepted" section before writing a long proposal.

## You are stuck on an exercise

Do this in order:

1. Re-read the chapter's prerequisites — most stuck-points are a gap
   one module earlier.
2. Run the matching demo in `examples/` and diff it against your code.
3. Only then ask, and show the graph code and the exact error.

## You disagree with a design choice

The curriculum prefers current, documented behavior over fashion, and
says so in the chapters. If you think a choice is wrong, open a
content-suggestion issue with a source that contradicts the chapter —
a changelog entry, a maintainer note, or a runnable repro. Arguments
from preference alone will not change the text.

## Response expectations

This is a maintained curriculum, not a support channel. Issues get
triaged weekly. If an issue sits for two weeks, a comment ping is
fair.
