# 08 Production - interview scenarios

Status: beta | Teaches: [08 Production](../../08-production/) | Part 2 of 2

1. "Ship the support agent. The platform team gives you two weeks. Sequence the work."
Order by what blocks the launch: the graph with the approval gate (already built and evaled); Postgres checkpointer wiring and thread-id mapping (persistence is the user-facing must); deployment via `langgraph build` onto the k8s cluster with secrets from the manager; the eval gate in CI plus the day-one alerts (tool-error rate, p95, escalation spike); the runbook and the rollback path. What does NOT make the two weeks: streaming polish, multi-region, cost tiering - named as fast-follows, in writing. Teaches: [01-langgraph-platform](../../08-production/01-langgraph-platform.md).

2. "A deploy renamed a state field. Half the resumed conversations broke. Postmortem?"
Cause: non-additive state migration with in-flight threads resuming against the new schema - the old checkpoints carry the old field name. Fix forward: a migration that backfills the renamed field across stored checkpoints, plus a compatibility read (accept both names) during the transition window. Prevention: the deploy checklist gains a state-compatibility line - additive fields only, or an explicit migration with a test that resumes a pre-deploy checkpoint. Teaches: [02-docker-and-checkpointing](../../08-production/04-checkpointing-and-durability.md).

3. "Your agent's Postgres checkpoint store is the largest table in the database. Ops is unhappy. Respond with a plan, not an apology."
Measure first: bytes by thread age, resume rate by age bracket (how often is a 90-day-old thread actually touched?), tenant distribution. Then policy: TTL aligned to product reality with archival to cold storage where audit requires retention, vacuum scheduling, and growth alarms so the next unhappiness is a dashboard line, not a surprise. The senior move: propose the retention number AND the product conversation that owns it. Teaches: [04-multi-tenant-considerations](../../08-production/04-checkpointing-and-durability.md).

4. "At 3 a.m. the escalation rate triples. You are on call. First fifteen minutes?"
The dashboard before the logs: which task family, which tenant, which step - spike localization. Then the two candidate classes: behavioral regression (a prompt or model change shipped - check the deploy timeline) or upstream failure (a tool erroring, the model adapting badly - check tool-error rate, which usually spikes first). Mitigation before diagnosis: roll back the last deploy, or disable the failing tool and let the graph route to humans. Then the eval row: the incident input joins the golden set before the fix ships. Teaches: [06-runbooks-and-incident-response](../../08-production/runbooks/).

5. "The CFO asks what the agent costs per quarter and whether it can be cut in half without 'breaking it.' Your response?"
Report cost per task family, not a lump sum: the top two families usually carry 70 percent (the classification-heavy ones), so the cut is tiering and caching there - bounded tools and trimmed context buy the rest. "Without breaking it" = the eval gate runs on every cost change; the number that cannot move is the accuracy baseline. Deliverable: a cost curve per family with the eval-checked cut points marked. Teaches: [03-cost-optimization](../../08-production/05-cost-optimization.md).

6. "Tenant A's traffic spike starves everyone else's latency. Fix without splitting the deployment."
Fair-share at the queue and the model-client pools: per-tenant concurrency caps and rate limits, priority lanes for the contract tiers, and backpressure - a tenant's requests queue behind their own cap, not others' work. The metering that pays for it: per-tenant queue-depth metrics and cost attribution, which the platform needs anyway. Split deployments are the LAST resort, and only when isolation is contractual, not performance-shaped. Teaches: [04-multi-tenant-considerations](../../08-production/04-checkpointing-and-durability.md).

7. "Your agent must run in the EU region with data residency. What actually changes?"
The state and the traffic: checkpointer and store on EU Postgres, inference egress pinned to EU-available endpoints, tool backends reachable from the region, and logs/traces tagged and retained regionally. What does not change: the graph code - the deployment is regional, the artifact is the same image. The interview bar: say "residency is a data-flow property," and enumerate where the data flows (state, traces, tool payloads), not just where the pods run. Teaches: [05-governance-and-compliance](../../08-production/06-governance-and-safety.md).

8. "Compliance asks: 'prove the agent cannot issue refunds without a named approver.' What do you show them?"
Three artifacts: the graph structure (the interrupt before the refund tool - structural, not prompt-level), the trajectory eval that asserts no refund executes without a resume event, running in CI on every change; and the audit extract from the checkpointer - refund events joined to their approver identities. Then the honest scope statement: what is proven, on which dataset, as of which version. Teaches: [05-governance-and-compliance](../../08-production/06-governance-and-safety.md) with [03-trajectory-evals](../../06-evals-and-observability/04-protocol-evals.md).

9. "The model provider deprecates your model tier on a 90-day clock. Plan the migration."
Inventory: where the tier is set (one config point, or scattered literals - if scattered, that is step zero). Then the eval matrix: current tier vs successor on the full suite - accuracy, trajectory shape, cost, latency. Then staged rollout: canary traffic, comparison dashboards, then full cutover and baseline update with a changelog entry. The 90-day clock's real deadline is the canary, not the cutover - backwards planning from the deprecation date, stated out loud. Teaches: [07-continuous-improvement](../../08-production/07-continuous-improvement.md).

10. "Your runbook for 'agent behaves weirdly' says 'check logs.' Rewrite the entry."
Symptom table first: weird = wrong tool? loop? refusal? tone? Each symptom names its dashboard panel (tool-error rate, step count, refusal rate, judge score) and its two-minute triage: deploy timeline, tenant, task family, one trace opened. Decision rules: rollback if a deploy correlates, tool-disable if a tool correlates, escalate to the eval owner if behavior regressed with no deploy. A runbook entry is a decision tree an on-call can execute half-asleep - that is the standard to state. Teaches: [06-runbooks-and-incident-response](../../08-production/runbooks/).
