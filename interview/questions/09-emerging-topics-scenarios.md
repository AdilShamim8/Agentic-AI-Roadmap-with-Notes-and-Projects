# 09 Emerging topics - interview scenarios

Status: beta | Teaches: [09 Emerging topics](../../09-emerging-topics/) | Part 2 of 2

1. "Your roadmap has a 'self-improving agent' item. An engineer asks what it means concretely. Answer."
Translate it into the pipeline it actually is: traces and failures are clustered weekly, the top clusters become golden rows, prompt and tool fixes ship against them, the gate holds the baseline, and memory consolidation (distilling recurring lessons into the Store) runs offline. What it does NOT mean: the model rewriting itself, unsupervised. The delivery: "self-improvement here is a data pipeline with a regression gate - here are the stages, here is the human checkpoint." Teaches: [05-self-improving-agents](../../09-emerging-topics/05-self-improving-agents.md).

2. "Your agent runs unattended overnight jobs. What does 'safe autonomy' mean at 3 a.m.?"
Bounded blast radius: the overnight scope uses read-and-propose tools, not execute tools; destructive capability requires an approval that waits for a human morning window; the run budget caps steps and spend so a loop cannot burn the night; and anomaly detection halts the run - deviation from the trajectory profile pauses rather than improvises. Autonomy is a spectrum you set with tool scopes and budgets, not a switch. Teaches: [06-safety-and-alignment](../../09-emerging-topics/07-safety-and-alignment.md).

3. "A vendor pitches their 'agent OS' as the answer to your plumbing. How do you evaluate it?"
Score it against the stack you would otherwise build: does it standardize the boundaries you care about (MCP tool access, A2A interop, memory conventions), or lock you into proprietary ones? What happens to your golden set, eval gate, and traces on their runtime - can you export them? And what is the exit cost - protocol-based boundaries port, proprietary ones do not. The verdict frame: platforms are adoptable exactly to the degree they keep the boundaries standard and the judgment yours. Teaches: [01-agent-os](../../09-emerging-topics/01-agent-os-and-kernels.md).

4. "Your agent's memory is a growing blob of facts, and answers cite year-old preferences. Fix the memory design."
Structure it: typed memory (facts with provenance and timestamps, preferences with decay, procedures separate), a write policy that updates rather than appends, and retrieval that prefers recency for volatile classes. Add the memory eval: rows where the correct answer depends on a NEWER fact outranking an older one. The principle: memory needs a schema and a lifecycle, or it becomes a swamp that degrades answers slowly enough to evade endpoint metrics. Teaches: [02-long-horizon-memory](../../09-emerging-topics/02-long-horizon-memory.md).

5. "Security asks how a prompt injection in a web page your browsing agent reads could escalate. Model the attack."
The chain: page content enters as tool output, the model treats it as instruction, the injected instruction targets a capability - exfiltrate data via another tool, or click a malicious action. The mitigations, in layers: content is quoted and marked untrusted in context; capability is scoped (the browsing agent's tools cannot write or send data); destructive clicks need approval; and the trajectory eval carries injection canaries. The sentence for security: "we assume the model can be manipulated; therefore the tool scopes, not the model's judgment, are the perimeter." Teaches: [04-agentic-browsers](../../09-emerging-topics/04-agentic-browsers.md) and [06-safety-and-alignment](../../09-emerging-topics/07-safety-and-alignment.md).

6. "Your CTO read about autonomous SDLC agents and wants yours by next quarter. Set realistic scope."
Scoped slice: bugfix-shaped tasks - repro from issue, patch, run tests, open PR, human merges. The leash is verification: the test suite decides success, the PR gate is the human. What is explicitly out: architecture work, multi-file refactors, anything whose correctness tests cannot check. The rollout: internal repo first, trajectory-reviewed for a month, then a second team. The sentence: "autonomy is earned per task class by the strength of its check - we start where checks are strongest." Teaches: [03-autonomous-sdlc](../../09-emerging-topics/03-autonomous-sdlc.md).

7. "You get to place one bet on an emerging capability for your team next year. What do you pick, and how do you defend it?"
A defensible shape: pick the one adjacent to your measured bottleneck - e.g., if trajectory data shows context and memory failures dominate, bet on long-horizon memory tooling; if integration dominates, bet on MCP consolidation. The defense: the eval and trace data that named the bottleneck, a small probe project with success metrics, and an explicit kill criterion. The interview bar is not the pick - it is the method for picking. Teaches: [08-when-to-use-which](../../05-agentic-patterns/08-when-to-use-which.md) applied forward.

8. "Regulators ask who is responsible when two agents over A2A produce a harmful outcome jointly."
The audit answer: responsibility follows the action - whichever agent executed the harmful tool owns it, with the delegation chain (who asked, under what instruction, with what contract) as contributing context. The engineering duty this implies: every cross-agent task logged with caller identity, every capability scoped, every destructive action gated where it executes. Governance in composed systems is attribution engineering - build the logs that make the question answerable. Teaches: [03-a2a-protocol](../../07-multi-agent-and-a2a/03-a2a-protocol.md) and [05-governance-and-compliance](../../08-production/06-governance-and-safety.md).

9. "Your agent's model provider ships a version with 20 percent better benchmark scores. Do you upgrade?"
Benchmarks are not your task: run the eval matrix - golden set, trajectory shape, cost, latency - and decide on your numbers. Then staged rollout with comparison dashboards. The broader point, worth saying in the interview: as the field accelerates, the teams that win are the ones whose eval harness makes upgrade decisions cheap and safe; everyone else is guessing on other people's benchmarks. Teaches: [07-continuous-improvement](../../08-production/07-continuous-improvement.md).

10. "Ten years of 'this changes everything' - how do you keep engineering judgment stable through the hype?"
Anchor on invariants: state must be managed, tools must be bounded, behavior must be measured, humans must sit at the destructive boundary, and interfaces at the protocol layer outlive products. Evaluate each wave against the invariants - the wave that changes how you satisfy them is real; the wave that asks you to abandon them is a demo. The career version of this answer is the whole [field guide](../../field-guide/) in one paragraph: judgment is the compounding asset, tools are the churn. Teaches: [02-skills-that-matter](../../field-guide/02-skills-that-matter.md).
